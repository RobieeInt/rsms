- Web and API are two parallel route trees over the same domains. `routes/api.php` wraps everything in `Route::name('api.')->group(...)` specifically so API route names (e.g. `api.clients.index`) never collide with the identically-named web ones (`clients.index`) — without the prefix, whichever route file loads last wins the name lookup. Preserve this prefix when adding new API routes.
- Livewire domain folders (`app/Livewire/<Domain>/`) follow a `*List` / `*Form` / `*Show` naming split; `*Form` is shared for both create and edit (route param optional). Follow this pattern for new domains rather than separate Create/Edit components.
- API responses go through `app/Http/Resources/`, one resource per model, mirroring the Livewire domain split — don't return raw models from `Api\*Controller`.
- Authorization is centralized: Policies live in `app/Policies/` and are registered explicitly in `AppServiceProvider::boot()` via `Gate::policy(...)` — NOT relying on Laravel's policy auto-discovery convention. When adding a policy for a new model, register it there or it silently won't apply.
- Public/unauthenticated-but-secure endpoints (PDF downloads, quotation approval) use Laravel's `signed` URL middleware rather than tokens in the DB, except quotation approval which additionally uses a stored token (`/quotation/approve/{token}`).
- Scheduled billing/reminders are Artisan commands in `app/Console/Commands/`, not queued jobs: `GenerateMonthlyInvoices`, `SendPaymentReminders`, `SendScheduleReminders` — check `routes/console.php` or the scheduler for cadence before assuming when they run.
- Tailwind v4 `@utility` custom utilities only (not `@apply`/`@layer components`). Dark mode toggled via localStorage key `rsms_dark_mode`, not Tailwind's class strategy alone.
- Mobile-first layout in `resources/views/layouts/app.blade.php`: slide-over sidebar (Alpine `sidebarOpen` state on `<body>`), fixed bottom nav (5 tabs) on mobile, hidden on `lg+`.
